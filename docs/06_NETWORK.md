# Сеть игры СИГНАЛЫ — протокол центра

> Создан 15.11.2026, сессия П3. Обновлён 16.11.2026, сессия П5 (один вход, «от имени», анонимно, отложенно, точка доступа); 19.11.2026, сессия П13 (общие переменные `var:<имя>`, «прибавить», правила с условием). Для приложения игрока, пульта мастера и **будущего сетевого модуля терминала Twine** (решение П-19: модуль движка — в ближайшей сессии движка). Код центра — `android/app/src/main/java/ru/signaly/net/` (чистая Java, без библиотек), проверки — `tests/net-test.mjs`, `tests/net-e2e.mjs`.

## 1. Устройство
- **Центр** — один телефон с приложением: пульт мастера → «Запустить центр на этом телефоне». Это WebSocket-сервер на порту **8790** внутри APK (служба Android, работает с погашенным экраном). Состояние центра сохраняется в файл и переживает перезапуск.
- **Wi-Fi** без интернета. **На игре — точка доступа на телефоне мастера, он же центр** (П-38: через роутер телефоны друг друга не видят). Все устройства в одной сети: 10 телефонов и терминал.
- **Адрес** центра раздаётся QR-кодом `SGNET:ws://192.168.1.20:8790` (пульт показывает его на экране). С П14 (П-62) QR не обязателен: телефон после входа сам ищет центр — порт 8790 на шлюзе Wi-Fi, затем по всей подсети /24 и на адресах точек доступа по умолчанию; найденный адрес запоминается (`SgLink.AUTO`, `finder`).
- **Клиенты**: телефоны игроков (роль `phone`), мастерский телефон (`master`), терминал (`terminal`). Обычный браузер по `http://IP:8790/` видит строку `SIGNALY CENTER OK`.
- Центр **ничего не знает о пакете игры**: пересылает сообщения, хранит общее состояние, считает выдачи, выполняет присланные правила и таймеры. Смысл сообщений понимают клиенты.

## 2. Сообщения (JSON, текстовые кадры WebSocket)

### Клиент → центр
| `t` | Поля | Что делает |
|---|---|---|
| `hello` | `role`, `dev` (id устройства), `acc` (id аккаунта или null), `name`, `ver`, `epoch`, `since` | Первое сообщение. Можно повторить (сменился аккаунт). Центр отвечает `welcome` и присылает пропущенные `msg` с номером больше `since` (если `epoch` совпала) |
| `msg` | `id` (уникальный, для защиты от повторов), `to` (список адресов), `kind`, `body`, `at` (необязательно) | Сообщение. Центр даёт ему номер `seq`, хранит в журнале, доставляет адресатам, отправителю — `ack`. **`at`** (часы центра) в будущем — отложенная отправка (П-43): центр держит сообщение до `at`, отправителю — `ack` с `later: true`, мастерам — `later`; в срок доставляет от имени отправителя и шлёт ему `ack` с `seq` |
| `set` | `key`, `value` (`null` — удалить); `add`, `base` (П13) | Общее состояние. Всем — `state`. С числом `add` центр прибавляет его к нынешнему значению ключа (нет значения — к `base` или 0), `value` тогда не важен |
| `claim` | `id`, `key`, `acc`, `limit` (0 — без предела), `per` (одному аккаунту один раз), `sign` (сколько подписей), `window` (секунд на подписи) | «Можно ли взять»: ограниченные коды, общий счёт, подписи. Ответ — `claimed` |
| `rules` | `ver`, `list` | Только `master`. Правила центра (раздел 4) |
| `timer` | `id`, `at` или `delay` (мс), `every` (мс, повтор), `emit` (список сообщений) / `cancel: true` | Отложенные и повторяющиеся сообщения |
| `admin` | `op: 'reset'` / `op: 'unclaim', key` / `op: 'drop', id` | Только `master`. Сброс центра перед новой игрой (новая `epoch`); `drop` — удалить отложенное сообщение (отправителю и мастерам — `dropped`) |
| `ping` | `id` | Ответ `pong` со временем центра |

### Центр → клиент
| `t` | Поля |
|---|---|
| `welcome` | `epoch`, `seq` (последний номер), `now` (время центра, мс), `state` (всё состояние), `rulesVer`, `peers` и `later` (мастеру) |
| `busy` | `acc`, `name` — этот аккаунт уже в сети на другом телефоне (П-39). Центр считает телефон «без аккаунта»; приложение выходит на экран входа |
| `later` | `list` — отложенные сообщения (мастерам) |
| `dropped` | `id` — мастер удалил отложенное сообщение (у отправителя оно остаётся с ⏱ — П-57) |
| `msg` | `seq`, `at`, `id`, `from: {dev, acc, role, name}` (`role: 'center'` — от правил), `to`, `kind`, `body` |
| `state` | `key`, `value`, `by` |
| `claimed` | `id`, `key`, `ok`, `reason` (`mine` / `empty` / `wait`), `n` (номер выдачи), `mine` (выдач этому аккаунту), `left`, `have`/`need`/`signers` (подписи) |
| `ack` | `id`, `seq`, `dup`; для отложенного — `later: true`, `at` |
| `peers` | список `{dev, acc, role, name, ver, online, last, ip}` — мастерам |
| `reset` | `epoch` |

**Адреса `to`:** `all`, `acc:<id аккаунта>`, `num:<номер сотрудника терминала>` (П9: `num` из `hello`, поле персонажа «Номер на терминале»; центр пишет его и в `from`), `role:terminal`, `role:master`, `dev:<id устройства>`. Мастер получает **всё**. Пустой `to` = `all`.

**Время:** `now`/`at`/`until` — часы центра. Клиент держит поправку `offset = now − Date.now()`.

**Повтор после разрыва:** клиент помнит `epoch` и последний `seq`. Если центр перезапущен и не успел записать последние сообщения (его `seq` меньше нашего) — клиент берёт `seq` центра.

## 3. Что значат `kind` и ключи состояния
| `kind` (`msg`) | `body` | Кто понимает |
|---|---|---|
| `chat` | `text`, `photo` (data URL JPEG), `sys` (от системы), `as: {acc, name}` (мастер пишет от имени — П-40; от не-мастера центр поле убирает; `acc: '@boss'` — «Руководитель»), `anon` (анонимно — П-42: не-мастерам центр присылает `from: {anon: true}`), `color` (`#rrggbb` — цвет отправителя в чужих чатах, П-51; у анонимных нет). Снимок с версии П6 — серый, окрашивает получатель | телефоны, мастер, терминал (общий канал) |
| `color` | `offer: true` — «Хотите сменить цвет?»; `set: id палитры` (пусто — по умолчанию); `any: true/false` — кнопка ◐ до конца главы (П-52, П-53) | телефоны |
| `notify` | `title`, `text` | телефоны: окно + шторка Android |
| `open` | `blocks` (id блоков), `title` | телефоны: открыть блоки |
| `glitch` / `fix` | `id` сбоя (пусто — все) | телефоны |
| `module` | `id` функции, `on`: `on` / `broken` / `denied` / `hidden` | телефоны |
| `app` | `id` прибора | телефоны |
| `signed` | `key`, `signers` | телефоны (вторая подпись пришла) |
| `term` | `set: {переменная: значение}`; `add: {переменная: N}` (П13 — прибавить) | **терминал**: записать переменные SugarCube |
| `event` | `name` | **центр** (правила), мастер, терминал |
| `code` | `code`, `phrase`, `label`, `acc`, `num`, `voice` | **терминал** (П9): на телефоне открыли код или услышана фраза «для терминала» (П-60); условие Twine `setup.phone("code", …)` |
| `vote-close` | `id`, `term` (переменная итога), `options` | терминал и мастер: голосование закончилось |

| Ключ (`set`) | Значение |
|---|---|
| `chapter` | `{n, at, force}` — глава для всех (`force` — можно и назад). Побеждает более позднее `at` |
| `alarm` | `{on, id, title, text, red, full, siren, vibrate, torch, jam, at}` — аварийный режим |
| `countdown` | `{on, title, until, at}` — общий обратный отсчёт |
| `vote` | `{on, id, title, options[], until, to[], term}` — голосование |
| `v:<id голосования>:<id аккаунта>` | номер выбранного варианта |
| `claim:<ключ>` | `{n, limit}` — сколько раз взяли (видят все, в т. ч. терминал) |
| `auto` | `false` — мастер выключил правила и повторы |
| `var:<имя>` | значение **общей переменной** терминала и телефонов (П13, Т4-3): пишут терминал (движок 31, `<<sg-shared>>` в StoryInit), коды телефонов (действие «Переменная терминала»), правила и пульт; телефоны подставляют в `{{имя}}`, терминал — в `$имя` |

## 4. Правила центра
Список `rules` присылает мастерский телефон (собран из пакета: вкладка «Сеть и события» → «Правила», таймеры уведомлений, повторы голосований). Центр выполняет их сам, пока `auto` не `false`.
- `{id, on: 'event', event: 'имя', chapters: [], emit: [...]}` — пришло `msg` с `kind: 'event'` и этим `body.name`.
- `{id, on: 'state', key: 'chapter', n: 2, emit: [...]}` — состояние `chapter` стало `n`.
- `{id, on: 'every', every: мс, chapters: [], emit: [...]}` — повтор (не чаще раза в 5 с).
- `{id, on: 'state', key: 'var:имя', test: {op, value}, init, chapters: [], emit: [...]}` — (П13) общая переменная: когда условие `op` (= != > >= < <=) стало верным (было неверным); нет значения — `init`. Прошлое значение условия центр держит в памяти (после перезапуска и сброса — по нынешнему состоянию, без срабатывания).
- `{id, on: 'bounds', key: 'var:имя', min, max}` — (П15) предел общей переменной: любое `set` (телефон, терминал, пульт, правило) с числом вне `min…max` записывается как `min` или `max`; тогда же — правила `limit`.
- `{id, on: 'limit', key: 'var:имя', side: 'max'|'min'|'any', chapters: [], emit: [...]}` — (П15) «упёрлась в предел»: кто-то попытался выйти за предел `bounds` (значение осталось на пределе); срабатывает каждый раз.

`emit` — сообщения `{t: 'msg', …}` или `{t: 'set', …}`, у каждого может быть `delay` (мс). В строках подставляется `{{now}}` и `{{now+N}}` (время центра; если строка — только шаблон, получается число).

## 5. Терминал Twine (для сессии движка)
**С П9 / сессии движка 31 — в движке 28:** модуль скопирован в `twine-signaly` (`signaly-net-module.ts`), действие «Телефонам: …» (`<<sg-net …>>`), условие «Пришло с телефона» (`setup.phone`), переменные с пульта и итог голосования пишет движок (`ownVars`). Ниже — история П7.
**Готово с П7:** модуль `src/terminal/sg-term-net.js` (MIT, без кода движка) — всё из пп. 1–3 и `notify`/`set`/`chat`; окно «Сеть» (Ctrl+Shift+N или огонёк в правом нижнем углу): адрес вручную, QR «СЕТЬ» камерой ноутбука (jsQR), «НАЙТИ» (192.168.43.1, 172.20.10.1, 192.168.N.1 — на Android 11+ адрес точки бывает случайным, тогда вручную или QR); адрес запоминается. SugarCube: `<<sg-net-notify "Заголовок" "Текст" ["acc:id" …]>>`, `<<sg-net-event "имя">>`, `<<sg-net-set "ключ" значение>>`, `<<sg-net-panel>>`; `term` пишет в `State.variables`. Проба — `dist/terminal-probe.html` и `.twee` (`tools/build-term.mjs`), проверка — `tests/terminal-test.mjs`. Встроить в движок (блок «СИГНАЛЫ: движок терминала», формы) — в сессии движка.
Минимум сетевого модуля:
1. Подключиться к `ws://IP:8790` (адрес — настройка мастера в терминале; Chrome 142+ один раз спросит разрешение на доступ к локальной сети), отправить `{t:'hello', role:'terminal', dev:'terminal-1', name:'Терминал'}`, переподключаться при разрыве.
2. **Событие** «в терминале X» → `{t:'msg', id, to:['role:master'], kind:'event', body:{name:'X'}}`. Правила из редактора приложения (решение П-20) превратят его в уведомления, аварию, открытие блоков у нужных персонажей.
3. **Принять** `msg` с `kind:'term'` → записать переменные (`State.variables`), с `kind:'vote-close'` → посчитать голоса по ключам `v:<id>:*` из `state` и записать итог в переменную `term` (например, выбрать альбом радио).
4. По желанию: включить/выключить аварию (`set alarm`), прислать список открытых альбомов для голосования (`set vote` с `options`), показать общий канал (`chat` с `to: ['all']`), прочитать `claim:*` (сколько ампул взяли).
5. Мастер на терминале работает со своей клавиатурой и мышью (решение П-15) — сетевые кнопки мастера в терминале можно повесить на них.

## 6. Android
- Служба `SgNetService` (тип `specialUse`: без 6-часового предела `dataSync`, игра идёт ~12 часов) держит связь и центр, частичную блокировку сна и Wi-Fi, показывает значок в шторке.
- Сама, без страницы: уведомления (`notify`, личные `chat`, `open`) в шторку; авария — сирена через поток будильника (громче беззвучного режима, громкость на максимум и обратно), вибрация, мигающий фонарик, окно поверх экрана блокировки.
- **Один персонаж — один телефон (П-39):** `hello` с аккаунтом, который уже в сети с другого `dev`, получает `busy`. Пропавший без закрытия телефон центр отпускает через ~25 с молчания (ping раз в 8 с).
- **Точка доступа (П-38):** после двух неудач подряд клиент пробует запасной адрес — шлюз сети Wi-Fi (центр с точкой доступа и есть шлюз; после перезапуска точки её адрес может смениться). Удачный адрес сообщается приложению и запоминается. Сеть Wi-Fi появилась или пропала — служба переподключается сразу.
- **Путь до центра:** сокет клиента привязывается к сети Wi-Fi, в подсети которой лежит адрес центра (`Network.bindSocket`) — в обход мобильных данных (Wi-Fi без интернета) и VPN, если VPN разрешает обход. Причина неудачи (`timeout`, `refused`, `unreach`, `notcenter`, `badaddr`, `denied`, `lost`) и проверка сети (VPN, Wi-Fi, та же подсеть) уходят на экран «СЕТЬ».
- Мост в JS — плагин `SgNet` (`connect`, `setHello`, `send`, `drain`, `status`, `startCenter`, `stopCenter`, `alarm`, `notify`, `keepScreen`, `battery`).
