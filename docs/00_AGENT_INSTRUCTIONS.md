## Главные правила
1. **Репозиторий открытый.** Тексты игры, коды, имена персонажей и тайны сюжета сюда не попадают. Наполнение живёт только в пакетах `.sgpack` у автора. Тестовые данные в `tests/` вымышленные и нейтральные.
2. **Решения автора** записываются в `docs/05_DECISIONS.md` (номер П-N, дата, вопрос, решение); П-1…П-60 — дословно в архиве `docs/05а_DECISIONS_ARCHIVE.md` (закрытый том, П20; старое — `grep '| П-NN |'` там). Состояние, открытые вопросы и журнал сессий — в проекте, `claude/13_ПРИЛОЖЕНИЕ.md` (там же порядок сессии «Приложение»). Возможность, о которой автор не просил, сначала задаётся ему вопросом.
3. **Вопросы задаются порциями, сгруппированными по темам** (можно больше 7, если оправдано — П-12). К каждому: что это даёт в игре, твоя рекомендация, варианты ответа. Пришли ответы на вопросы, которых нет в `claude/13` и `docs/05` (например, «10-1 А»), — сразу спроси автора текст вопроса; не ищи по проекту и архивам.
4. **Формат пакета `.sgpack`** (`game.json` + `media/`) должен оставаться обратно совместимым. Старый пакет обязан открываться в новом редакторе и приложении. Новые поля получают значения по умолчанию в `SG.normalize`. Если меняется смысл поля, увеличь `FORMAT` и добавь перенос.

## Технические заметки
- **П20, окружение облачной сессии:** ветка по умолчанию на GitHub — старая `session-01`: клонировать `--branch main`. Браузер Playwright может не скачаться (`npx playwright install` молчит) — проверки запускать через обёртку на системный Chrome (`chromium.launch` с `executablePath: '/usr/bin/google-chrome'`, `--no-sandbox`; путь к обёртке — первым аргументом вместо `playwright`). С ним «ошибок на страницах нет» падает из-за «404» (так и на `main`, не наша ошибка) — на GitHub (свой Chromium) проходит. Две проверки сети одновременно не запускать: общая папка классов Java и порты.
- Сканер — `getUserMedia` + jsQR (`inversionAttempts: 'attemptBoth'`, поэтому светлый QR на тёмном фоне тоже читается), кадр уменьшается до 640 точек, проверка раз в 150 мс. QR может содержать `SG:` в начале, он отбрасывается.
- В WebView Capacitor камеру разрешает `BridgeWebChromeClient.onPermissionRequest`, выбор файла — `onShowFileChooser`; ничего дописывать не нужно.
- Кнопку «назад» Android обрабатывает плагин `@capacitor/app`: закрывает верхнее окно, на главном экране ничего не делает. В браузере окна живут в `history.pushState`.
- Редактор открыт из файла (file://): в Chrome это безопасный контекст, `showSaveFilePicker` работает. Запасной путь — скачивание; на file:// имя файла при скачивании может теряться.
- Playwright: `setInputFiles` с **путём** на кириллице молча не срабатывает. Передавай `{name, mimeType, buffer}`.
- Поддельная камера Chromium: `--use-file-for-fake-video-capture=<.y4m>`; видео собирается ffmpeg из JPG, который сохранил редактор.
- Поддельный микрофон: `--use-file-for-fake-audio-capture=<.wav>` (файл повторяется по кругу). В headless он иногда теряет ~10 мс звука — декодер SSTV это выдерживает (поправка по соседним импульсам), не убирать.
- Микрофон в WebView Capacitor разрешает тот же `BridgeWebChromeClient` (AUDIO_CAPTURE → RECORD_AUDIO), нужны только права в манифесте.
- Новый объект в редакторе (аккаунт, код) создаётся со всеми полями сразу: `normalize` для него не вызывается до перезагрузки.
- Эффект перехода (`#glitch`) снимается таймером: `forwards` у анимации со `steps` оставлял полосы на экране.
- Секреты Actions через прокси сессии не задаются (403). Поэтому есть общий ключ `android/keystore/signaly-public.jks`, пароль к нему лежит в workflow.
- Сетевой код на чистой Java — потому что Android SDK и Maven в песочнице недоступны, а `javac` есть: центр и клиент проверяются здесь, в APK компилируется тот же код. Android-часть (служба, плагин) проверяется только сборкой в Actions и на телефоне.
- Служба — `foregroundServiceType="specialUse"`: у `dataSync` в Android 15 предел 6 часов, а игра идёт ~12.
- В WebView страница `https://localhost`, поэтому `ws://` из JS считается смешанным содержимым. В APK соединение держит служба (Java), JS ходит через плагин; `allowMixedContent` не трогаем.
- Порты проверок: e2e — 8765, net-e2e — 8766 и центр 18795, net-test — 18790/18791, terminal-test — 18900–19300, stand-test — центр 18799 (стенд — из файла).
- **Стенд (П24):** все «телефоны» стенда идут через одно подключение ноутбука к Wi-Fi — он проверяет центр, приложение и доставку при 10 участниках, но не предел точки доступа по числу устройств и не радио; это — репетиция на настоящих телефонах. Chrome замедляет скрытые вкладки — стенд держать на экране. Служебные `stand`-сообщения остаются в журнале центра — после пробы «Сбросить центр».
- **Сеть на настоящих телефонах (П4, 16.11):** телефон игрока может не дойти до центра, хотя оба в одном Wi-Fi. Причины: включённый VPN (уводит 192.168.… в туннель; на снимках автора был значок ключа), изоляция клиентов роутера или гостевая сеть, Wi-Fi без интернета (Android шлёт трафик через мобильные данные). Поэтому сокет клиента привязывается к сети Wi-Fi, в подсети которой лежит центр (`Network.bindSocket`; VPN без разрешения обхода это запрещает — тогда совет выключить VPN), а окно «СЕТЬ» показывает причину и проверку: Wi-Fi, та же подсеть, VPN, «откройте http://IP:8790 в Chrome», запасной путь — точка доступа на телефоне-центре. `ACCESS_LOCAL_NETWORK` объявлено заранее: обязательным оно станет при targetSdk 37 (Android 17).
- **Точка доступа (П-38, проверка автора build-19):** через роутер квартиры телефоны центра не видят (изоляция клиентов), через точку доступа на телефоне мастера всё работает. Поэтому: центр — телефон мастера с точкой доступа; клиент после двух неудач пробует шлюз Wi-Fi (это и есть центр); при появлении/пропаже Wi-Fi переподключается сразу; молчащее соединение рвётся через 25 с (было 45). Игроку — кнопка «Переподключить» в окне «СЕТЬ» и совет проверить, что телефон не перескочил на домашний Wi-Fi.
- **Старые телефоны (Redmi Note 6 Pro, Android 9):** интерфейс «съезжал». Причины: крупный системный шрифт MIUI масштабирует текст WebView (`setTextZoom(100)` в `MainActivity`) и старый WebView без `color-mix` (Chrome 111), `inset` (87), `gap` у flex (84), `aspect-ratio` (88). В `player.css` их нет (кроме `gap` с запасом: скрипт в `index.html` ставит `html.nogap`, и в конце `player.css` — отступы полями), оттенки — переменными из `themeCss`. Версия WebView видна в режиме мастера; меньше 90 — совет обновить: на Android 7–9 WebView — это сам Google Chrome (обновлять его; «WebView Dev» там недоступен — проверка автора, С2), на Android 10+ — «Android System WebView». На Redmi Note 6 Pro с Chrome 70 интерфейс после П5 нормальный. Новое в стилях проверять по caniuse на Chrome 70+.
- **Своя клавиатура (П-54):** поле с `inputmode="none"` (Chrome 66+), клавиши не забирают фокус (`mousedown` → `preventDefault`), вставка по курсору, после — событие `input` (на нём автосохранение заметок и проверка вставки). Playwright `fill()` и `keyboard.type()` в такие поля работают как раньше.
- **Снимки (П-49):** одноцветный снимок сохраняется серым (оттенок белый), окрашивается при показе `P.tintPhoto` (`l = max(r,g,b)`). Снимки из старых версий — уже цветные, их не трогаем.
- **Тайны:** смысл сужения гаммы к одному цвету — сюжетный (журнал сюжета), в репозиторий не писать.
- **Голос (П-58).** Vosk: `com.alphacephei:vosk-android:0.3.47` + `jna:5.13.0@aar`, только ARM (`abiFilters`); APK ~67 МБ (модель ~88 МБ без сжатия, при первом запуске копируется в файлы приложения). Песочница до alphacephei.com и Maven не достаёт — модель и библиотека только в Actions; API Vosk сверять с `alphacep/vosk-api` на GitHub (`java/lib/src/main/java/org/vosk`). Режим грамматики: всё прочее → `[unk]`; фразы из слов словаря модели (неизвестное слово Vosk молча выбрасывает — проверять на телефоне: режим мастера → «Голос: проверка»). Микрофон в фоне (Android 11+) — только у службы с типом `microphone`, запущенной, пока приложение на экране (`SgNetService.startFg`; иначе `SecurityException` → без микрофона, текст «откройте приложение»). Служба держится и ради голоса без сети (`SgVoice.active()`).
- **Терминал и телефоны (П9).** Терминал адресует персонажа номером сотрудника (`account.num`, поле «Номер на терминале»): телефон шлёт `num` в `hello`, центр доставляет `num:<номер>`; **П23:** телефон и сам узнаёт `num:<свой номер>` (`toMe` в `player.js` — номер из пакета; `SgNetService.toMe` — `myNum` из `hello`), до П23 пропускал.
